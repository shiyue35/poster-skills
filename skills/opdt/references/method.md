# 开放首稿法 · 通用执行方法

技能版本 1.7.0，方法依据 opdt-v004。本文件维护行为规则，模板承接项目事实，审核协议定义如何核对实际请求。

## 1. 任务范围与决策边界

先确定本轮动作、对象、版本、数量、停止位置和已有授权。只读检查、文字讨论、查看或选稿不自动授权制图、保存或发布。用户已明确的同一决定不重复询问；本轮没有进入的阶段不执行。

| 任务 | 预期产物与边界 |
|---|---|
| 构图共创 | 建立供选择的布局示意，可用明确占位；不要求预先已有构图图或已选方案。 |
| 完整首稿／独立重做 | 一次统筹主体、文字和环境生成完整海报；仅相同风格或尺寸不代表选定旧母版。 |
| 局部修错 | 恢复现稿偏离的已确认要求，目标不变；在对应制作授权和预算内可处理，用户要求先看或不自动修时按其限制。 |
| 需求变更 | 改变已确认目标或约束，由用户先决定；用户已明确提出具体改法即构成该项决定，不再重复申请。 |
| 独立组件 | 按明确的母稿、设计依据或独立用途产出标题、背景、标识等指定组件；它不算完整首稿，也不能用于冒充完成整图首稿。 |
| 系列中的单稿视觉适配 | 常规套版由统筹按已选母版办理。若新对象在允许的换行、裁切或留白范围内仍放不下，接手该稿与具体冲突，核对对象输入、母版固定项和可调项，按授权给出实稿。 |

按动作分流，同一委托中可以既有首稿反馈，又有常规换名或补导。项目统筹是职责，现有项目执行者可以按已有制作表和归档约定办理已授权的常规工作，不依赖另装某个技能。只有需要新视觉取舍的稿件进入首稿流程。各项仍执行所在项目适用的检查，实际模型调用沿用同一请求的审核与预算规则。

规划时，每个方向用一两句话说明独特创意、预期观众感受及与其他候选的区别；单一方向说明预期感受即可，具体画法在开放范围内统筹。

例如：把错写日期改回已确认日期、把偏移主体恢复到已选布局属于修错；改到场日期、为美观缩小已确认主角或重排邀约属于变更。后者先说明原要求、拟改内容和影响，等待用户决定。修错若必须牺牲另一条已确认要求，也转为变更处理；无法判断时先问，不自设“微调”豁免。

纯文字规划不自动保存文件。获准共创后可用绘图／排版工具形成示意，或在独立审核后使用图像模型。非模型复制／导出不触发模型调用审核；普通导出只核对实际尺寸、格式、裁切与完整性，不自动重做内容。

## 2. 现行约定与输入依据

### 需求来源与适用范围

从项目入口读取本轮公共 brief、对象资料和适用风格要求，叠加本稿有效决定。分档项目按风格编号只读本轮相关文件；不同对象、风格和同名A／B不互借要求。

关键要求保留提出者、原始出处、对象／风格／版本／阶段和确认状态。文件较新、标题含“当前”、助手整理或自填通过不证明覆盖关系。长期决定在范围内持续有效；无法判断后续请求是同稿新版本还是独立新稿时，先确认单稿要求是否继续适用，不凭同风格或新版本号推定。

读取实际所需素材并说明身份、构图、风格、原件复用等用途；路径存在不等于已经查看。没有 brief 可继续获准的需求梳理；建立或维护文档须有对应授权。已有 brief 保留原结构和有效记录，不为套模板重排，不覆盖只读文件。获准的修改按公共、对象、风格或单稿职责同步；不可写时用允许的关联记录承接真实依据，无法追溯就报告缺口。

### 构图图片与用户选择

完整制作必须有用户已选、可读且实际传入的构图图片，表达分区、层级、相对体量和成组关系；文字不能替代。主体图或风格图不自动承担构图用途，已选完整海报可说明同时承担母版和构图参考。

缺图先告知用户，再共同明确要比较的布局并形成候选图，由用户选择。共创不受“先有图／先选定”的未来条件阻断；已适用的明确选择不重复确认。选定构图不自动授权海报制作，共创授权也不自动变成完整制作授权。

选图时区分已确认关系、仅示意参数和仍开放的视觉实现。示意字体、临时色块或坐标不自动成为硬要求。既定身份、姿态、道具、文案和构图关系保留；字体、配色、光色、材质、背景、装饰和留白仅在明确开放范围内设计，不要求用户先给全部HEX、字体名或像素坐标。拟改变已确认关系、主体／标识相对大小、字号、位置或间距时先确认；恢复偏差按第1节修错规则。

### 尺寸与工具能力

未指定规格时，原生目标和导出尺寸均默认宽1080×高1920像素（9:16）。已有明确规格按其适用范围执行；只有比例、宽高含义不明或多处规格冲突时先确认，不擅自转向默认规格。

原生目标写入提示词，生成后读取原件和导出的实际像素。写入目标不证明工具能锁定原生尺寸；已知不支持或无法保证时，在调用前说明能力边界并取得本轮处理决定，已有适用决定可沿用。未达到原生目标不得以放大导出冒充达标；按已确认处理方式执行，没有适用决定则先问。

### 调用预算

每次新的明确制作或改稿请求，按对象和方向重新计数；默认总调用最多3次，其中定向修正最多2轮。用户明确指定的次数、费用或跨请求总上限优先，当前请求超额须有明确授权。

同一请求内的共创与海报模型调用合并计数；自动重试、修正、阶段切换、换文件名或模型自增版本都不重置。是否新请求或是否同一方向不明时先问，不自行拆方向增加额度。调用发出后失败、超时也计数；只要针对已有画面修改就同时计一次修正，不能仅因含参考图就算修正。普通绘图、独立叠标和非模型导出不计图像模型调用。

### 身份与原件

要求真实呈现指定主体时，保留相应个体特征、姿态、完整轮廓和必要道具；零图像输入无法可靠还原时说明冲突，让用户决定身份素材、概念主体或其他调整，不能自行豁免。共创明确使用占位框不宣称身份还原，不因缺照片阻断。

原标志／字牌适用时保留原内容、颜色、比例和清晰度，可在整图中预留后独立叠回，尺寸服从 brief 中的角色与构图，辅助标识不抢主体或主标题。保留原貌不等于回嵌每个原像素；只对实际偏差校准。确需回嵌时保持已确认尺度、位置、朝向、遮挡、边缘和光影关系；无法做到时先按变更处理。

## 3. 分阶段检查与依据沿用

检查状态为未检查、通过、缺项、冲突；每项有原始依据，不预填通过。已核实的不适用项可记为通过并附理由，不能掩盖实际缺项；沿用项仍需有效的原始依据。分别报告“设计输入：齐全／待补或冲突／未核实”和“当前阶段：已获准动作、对象、数量及停止位置”。

### 构图共创的5项条件

| 编号 | 所需实质内容 |
|---|---|
| 1 | 对应共创制作授权、候选数量和停止在示意／用户选择的边界。 |
| 2 | 共同明确的布局问题、必要信息模块和目标画幅；不要求已有构图图或已选方案。 |
| 3 | 已有真实信息及限制保留；缺少的最终内容明示占位，不将未解决冲突伪装成占位。 |
| 4 | 实际使用的素材、用途和参数可核对；允许没有参考图片。 |
| 5 | 工具能力、当前请求预算、候选输出与状态明确；说明是否使用图像模型。 |

满足条件后，图像模型调用再取得对这5项的独立审核通过；审核结果不成为这5项自身的前提。非模型绘图无需模型调用审核。示意完成后核对分区、层级、体量和分组可读性，交用户选择，不登记为完整首稿或成品。

### 完整制作的10项条件

以下同时服务完整首稿、局部任务和系列延展，但实际产物按第1节任务范围决定。

| 编号 | 所需实质内容 |
|---|---|
| 1 | 传播目标、受众和本轮希望改善或判断的效果。 |
| 2 | 任务类型、当前授权、对象、版本、方向、数量、渠道和停止位置。 |
| 3 | 本轮需要保留或修改的准确文案、数字、口径、日期及归属，有原始依据。 |
| 4 | 本轮实际需要的主体或组件素材可用，身份、姿态、道具与裁切范围明确。 |
| 5 | 用户已选的构图图片及实际传入安排，分区、层级、相对体量和成组关系清楚。 |
| 6 | 真实事实与必画、可选、禁用场景分开；硬限制与冲突处理有据。 |
| 7 | 视觉目标、参考用途和开放空间明确，未指定的视觉实现不冒充缺项。 |
| 8 | 首稿整图方法，或局部任务的母稿／独立用途、保持项和修改项；延展的固定与适配项明确。 |
| 9 | 原生／导出规格、工具能力及已确认处理方式、本轮验收和真实可编辑范围可执行。 |
| 10 | 需求版本与确认状态可追溯，当前用户请求和预算依据真实，没有未解决的授权问题。 |

局部任务不重填另一套完整 brief：未变化且仍有效的原始依据可沿用，只复核变化及其影响，并说明哪些项沿用、哪些本次核对。对应组件不包含的主体或文案可据实标为不适用；需要保留的母稿信息仍受约束，不能以不适用放弃。每次请求仍有完整的适用检查结论，不能只写“沿用上次通过”。

当前阶段缺项不阻断其他已获授权且不依赖该缺项的工作。进入完整制作前，必须补齐本轮实际必需项；不以共创名义绕过选图、真实身份、文案或首稿方法。

## 4. 实际制作、修复与结果核对

调用图像模型前，对照原始要求核对实际提示词、图片顺序／用途和参数，并取得[独立审核](preflight-review.md#1-准备与独立审核)。审核绑定的输入或来源变化后复核受影响部分；已有检查结论不能代替实际输入核对。

完整首稿每方向独立整图生成，让主体、标题、光色、材质和留白共同设计。不能用空背景加抠图和系统字拼装替代。选定完整视觉后可按需分层；不能把生成位图称为可编辑文字工程。

局部修错／已确认变更只修改指定内容并保持其余部分；独立组件只产出获准组件，说明所依附母稿、设计依据或独立用途，以母稿或用户已选的组件构图作参考，不强制重新建立整张海报布局；不额外重做整张海报。组件不能用于把尚未完成的整图首稿伪装成已完成。接手统筹转回的单稿时，沿用母版固定项，核对该对象的真实输入，集中处理现有规则解决不了的视觉问题。

只写提示词时按任务分别给可复制文本和实际图片清单／顺序／用途，缺关键输入时标草案：
- 共创：布局目标、模块、候选范围、画幅、占位内容与实际素材；不要求预先已有构图图片。
- 完整首稿：需求与有效决定、对象、完整文案、主体保留项、已选构图图、方向目标和原标识复用安排，整图统筹。
- 局部／组件：指定母稿或设计依据、修错／已确认变更目标、准确新内容、保持项、输出范围和实际参考；不复制无关完整海报生成指令。

结果按本轮任务核对：文案／身份／道具、构图层级与体量、手机可读性、原标识比例与遮挡、实际尺寸和裁切；局部只核对修改项及其影响。位置正确、文案齐全或等比叠标都不能单独证明构图合格。多方向分别生成，必要时汇成对比图，不能以一张多格图替代独立首稿。

记录具体偏差和处理原因，在授权与预算内修错；需要改变目标时先确认。没有具体偏差不默认擦除整只主体重组。达到预算或无法满足硬要求时停止该方向调用，保存已有结果并报告缺口；其他独立获准方向可继续，不把问题稿记为全部通过。

## 5. 工具失败与轻量收尾

使用实际可用工具并遵守其接口要求，不假设插件、服务或组装软件存在。从零制作完整首稿／独立重做缺整图生成能力时，说明整图尚未生成，不改用背景拼装冒充。此项不阻断现有工具可完成、已获准且满足适用条件的非模型构图共创、现稿修改、独立组件处理或导出。审核不可用时仅停止相应模型调用，不用自审替代。

超时先查原请求状态、产物和工具可观察的计费信息；已有产物就取回。结果待定时等候或查询，计费不可观察就据实说明，不盲目重发或声称零请求。只有确认需要重新请求且预算允许才再调用；提供方收到请求后的错误不能当作未调用或自动退款。

必要产物按项目规则保存，保留原件、旧交付和工程依赖。共用事实、对象、风格和单稿资料按现有职责维护，同一事实不平行抄写。实际提示词、输入用途与来源、检查／审核、调用及确认状态简记一次，沿用既有记录，不另建例行归档报告。

在本轮约定的停点交回实际结果。只讨论或写提示词时直接给文字。探索轮在已有候选说明或审阅记录中定位用户看到的候选。制作轮在本稿记录中关联固定预览、工作版本、对应工程或底图，写明实际核对结果、可编辑范围及待决定事项。对约定的尺寸、透明度或分层状态如实说明。只有完成获准的制作和核对才记为本轮完成。

用户有决定时，关联可定位的原话和所见版本，说明适用稿件、阶段和用途。选构图记录布局，批准母版沿用记录范围，明确成品确认才可登记成品。一句话可以同时给出几种决定，保存一次依据，各处引用。审核通过只对应本次实际模型输入。

单独委托直接把结果交给用户。批量委托或用户随后要求正式归档、延展时，交给统筹同一稿件记录的入口，并指出结果、下一步及未决事项。如果原模型请求仍待核或预算影响续作，连同原调用记录交接。统筹依明确的母版授权安排延展，依成品确认办理正式归档。成品已确认但交付文件尚未导出，记为待导出。已导出待交付的文件，实际交给收件人后再登记已交付。对外发布需另有对应授权。

例如主审在主场 v003 固定预览下说“这张定稿，两张分场照这个构图做，先给我看其中一张”。本稿记录关联这条回复和对应底稿。统筹据此办理主场定稿，两张分场在现有工作单引用同一回复。本轮先做一张分场预览交主审，另一张等看稿反馈再推进。两张分场各自的成品状态等后续确认。

程序校验为可选宿主集成；维护时读[协议第4节](preflight-review.md#4-可选程序集成与验证)，不将本地校验等同于内置工具已被拦截。
