# 开放首稿法

在真实输入、明确授权和调用预算内，统筹主体、文字与环境生成完整视觉，供用户选稿并按反馈收敛。项目事实取自当前项目；现行约定以[方法第2节](references/method.md#2-现行约定与输入依据)为准，模板与审核协议引用这些规则。

## 识别任务并按需读取

| 当前请求 | 读取与执行 |
|---|---|
| 审阅技能 | 读取本入口及所涉方法、模板或脚本；不自动读取客户项目或修改文件。 |
| 检查、规划、只写提示词 | 读[方法第1—3节](references/method.md#1-任务范围与决策边界)，报告适用检查与缺口；提示词另读第4节对应骨架，停在获准阶段。 |
| 构图共创 | 告知缺图后与用户明确布局目标，执行共创5项条件；允许没有现成构图图或已选方案，候选形成后由用户选择。 |
| 完整首稿、独立重做 | 读方法第1—4节，执行完整制作10项检查；重做不自动沿用旧母版。 |
| 首稿反馈、视觉修错、组件设计 | 读方法第1—4节。标题压过主体、字牌需重新构图等视觉问题由开放首稿继续收敛。明确底稿、保持项和本轮可改范围。 |
| 按母版延展 | 统筹按获准名单和可变项安排套版。若某张用现有规则仍排不开，只将该张、母版和具体冲突交给开放首稿，按本次适配执行相应检查。 |
| 查看、选稿和审稿预览 | 按[方法第5节](references/method.md#5-工具失败与轻量收尾)交回本轮可查看的版本，记录用户实际选了什么及适用范围，停在获准阶段。 |
| 指定改色、复用组件、普通导出、取旧包或正式归档 | 属于项目统筹。按本项目已有工作单、工作副本或固定交付记录续办。混合委托逐项分流，首稿为审阅所需的预览仍由本稿执行者准备。 |

用户仅给技能名且对象或动作无法判断时简短询问；多个明确动作在授权范围内依次执行。“只读／只讨论／先给方案”限制优先；已有明确授权不重复申请。文档维护、制图、发布分别按实际授权判断。

## 保持的关键边界

- 完整首稿必须将主体、标题与环境整图统筹，不以空背景加原抠图和系统字体拼装替代；该约束不要求独立组件或局部改稿额外生成整张海报。
- 完整制作必须使用用户已选的构图图片；仅有文字不算图片。缺图先告知，再共创，不由模型代选或把候选记为已确认。
- 修错恢复已确认要求；改变已确认要求先由用户决定。拟改构图、主体／标识相对大小、已确认字号、位置或间距，不能以“微调”为由自行豁免。
- 保持身份、姿态、道具、逐字文案及硬限制；开放的视觉参数可由模型统筹。主体不默认整只回嵌，原标识按适用要求复用。
- 以原始用户决定及其适用范围判断需求，不把助手建议、历史单稿例外或“检查通过”当作授权；不伪造输入、审核、产物、确认状态或可编辑能力。

## 图像模型调用前独立审核

实际图像模型生成／编辑前读取[审核协议第1—3节](references/preflight-review.md#1-准备与独立审核)，由新上下文的只读子代理核对原始依据和实际输入；共创用5项，其余制作用10项。局部任务可引用未变化的原始证据，不接受制作代理的通过结论为前提。输入或来源变化后复核受影响部分。

审核不可用、故障或有未解决问题时停止相应模型调用；不以自审替代。非模型构图制图不触发模型调用审核，但仍须满足共创5项条件和对应授权。审核者无权代选构图或批准需求变更。

## 可选程序与交回稿件

仅在集成或维护受控执行器时读[审核协议第4节](references/preflight-review.md#4-可选程序集成与验证)和[校验模块](scripts/preflight_gate.py)；改动程序后运行[随包测试](scripts/test_preflight_gate.py)。模块不自动拦截内置生图，不能将本地测试称为全入口强制验收。

按项目既有结构保存必要产物，保护原件、旧交付和工程依赖。客户资料、产物及密钥留在获准的项目或服务位置。单独委托时直接向用户交回约定结果。协作时按[收尾与交接](references/method.md#5-工具失败与轻量收尾)交回同一条稿件记录，统筹依据明确的批准办理延展或正式归档。

示例：
- `$opdt 检查当前 brief，只读。`
- `$opdt 缺构图图，先和我共创候选让我选。`
- `$opdt 按已选构图生成一张完整首稿。`
- `$opdt 这版标题抢过了主角，保留已选构图，先给我看修改后的首稿。`
